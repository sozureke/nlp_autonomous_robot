## Natural Language Driven Autonomous Mobile Robot

### Purpose of This Document
Этот документ фиксирует:

- границы системы,
- основные подсистемы и их ответственность,
- выбранный академический фокус,
- критерии завершённости проекта (state of done).
  
Документ является точкой истины для дальнейшей разработки.  
Любая реализация должна соответствовать этому описанию.

### System Overview
Проект представляет собой автономную робототехническую систему, в которой:

- пользователь задаёт команды на естественном языке,
- система интерпретирует смысл команды,
- формирует план действий,
- исполняет его в замкнутом цикле управления,
- сначала в симуляции, затем на реальном роботе.
    
Ключевой принцип: интеллект системы полностью отделён от исполнения

### System Boundary
Что входит в систему:

- интерпретация текстовых команд,
- логическое принятие решений,
- управление движением через абстрактный API,
- моделирование мира на символическом уровне,
- симуляция среды,
- интеграция с реальным роботом как исполнительным устройством

### High-level Architecture

```
						User Command (text)
						        ↓
						Intent Parsing (NLP)
						        ↓
						Intent + Parameters
						        ↓
						Planner / Reasoning
						        ↓
						 .   (v, ω)
						        ↓
						Robot API (Contract)
						        ↓
						SimRobot / RealRobot
						        ↓
						RobotState (raw sensors)
						        ↓
						World Model (symbolic)
						        ↺
```

### Core Subsystems
#### Command Interface
Принимает текстовую команду пользователя. Однако, не интеритирует смысл, не принимает решений и не взаимодействует с роботом

#### NLP / Intent Parsing
Преобразует текст в структурированное представление (intent, parameters). Однако не управляет роботом, не читает сенсоры и не реализует поведение.

Используем:

- tokenizer
- POS-tagger
- dependency parse
  
##### Пример команды
“Move forward until you see an obstacle, then stop”

##### Tokenization + POS
spaCy даёт:
- глаголы (`move`, `stop`)
- направления (`forward`)
- условия (`until`)
- объекты (`obstacle`)
- численные параметры (если есть)
    
##### Intent classification (rule-driven)
Не regex по строке, а логические правила по лингвистическим признакам.

##### Slot filling
Извлекаем параметры:

- скорость (default / указана)
- расстояние
- направление
- условия
    
```py
Intent( type=IntentType.MOVE_UNTIL_OBSTACLE, speed=0.5, threshold=0.3 )`  
```

#### Robot API (Contract)
Единный формальный интерфейс между логикой и исполнением. Он одинаков как для симуляции как для реального робота, не содержит логики поведения и я вляется стабильной точкой архитектуры

#### Robot State (Raw Perception)
Представляет сырые сенсорные данные, полученные от робота. Он не интерпритирует смысл, а лишь отражает измерения

#### World Model
Символичное представление локального мира, получаемое из Robot State. Он определяет perception от reasoning и позволяет planner работать с логическими фактами. Он не содержит памяти и не является картой

#### Planning / Reasoning Core
Принимает intent и World Model, принимает решения и управляет роботом через Robot API. Он rule based, deterministic, explainable. Однако он не должен знать тип робота, источников сенсоров и парсить текст

#### Sim Robot
Симулирует физическое движение, эмуляцию сенсоров и реализует Robot API. Используется для откладки и тестирования

### Делать:

- собственную 2D симуляцию
- с шагом времени
- с явной моделью мира
- с логированием
    
### Не делать:
- сложную физику
- тяжёлые движки

#### Real Robot
Проксирует команды в hardware и возвращает реальые сенсорные данные, но не содержит логики, правил и не принимает никаких решений.

### State of Done

- [ ] пользователь вводит текстовую команду,
- [ ] система извлекает intent и параметры,
- [ ] planner автономно управляет роботом,
- [ ] поведение работает:
    - в симуляции,
    - на реальном роботе,
- [ ] код planner не изменяется при переходе Sim → Real,
- [ ] используется явная World Model.

### Development Order
#### Phase 1: Robot API (Contract)
**Файл:** `src/core/robot_api.py`

**Задачи:**
- [ ] Завершить определение `RobotState` со всеми необходимыми полями сенсоров
- [ ] Убедиться, что `BaseRobot` содержит все необходимые методы
- [ ] Добавить валидацию параметров (например, диапазоны для `move()`)
- [ ] Добавить полную документацию и type hints
- [ ] Написать unit-тесты для контракта (можно с mock-объектами)

**Критерий завершения:**
- `BaseRobot` и `RobotState` полностью определены и стабильны
- Интерфейс не будет изменяться в последующих фазах
- Тесты проходят

#### Phase 2: World Model
**Файл:** `src/core/world_model.py`

**Задачи:**
- [ ] Создать класс `WorldModel` для символического представления
- [ ] Реализовать метод `update(robot_state: RobotState)` для конвертации сырых данных
- [ ] Добавить методы-предикаты для запросов (например, `is_obstacle_ahead()`, `get_distance_to_obstacle()`)
- [ ] Убедиться, что модель не содержит памяти/истории
- [ ] Написать тесты с mock `RobotState`

**Критерий завершения:**
- `WorldModel` может преобразовать `RobotState` в логические факты
- Planner может использовать `WorldModel` для принятия решений
- Тесты проходят

#### Phase 3: Planner / Reasoning Core
**Файл:** `src/core/planner.py`

**Задачи:**
- [ ] Определить структуру `Intent` (dataclass с типом и параметрами)
- [ ] Создать enum `IntentType` (например, `STOP_AT_DISTANCE`, `CONDITIONAL_TURN`)
- [ ] Реализовать обработчики для каждого типа intent
- [ ] Создать основной цикл управления: `sense → reason → act`
- [ ] Реализовать rule-based логику для каждого поведения
- [ ] Написать тесты с mock `WorldModel` и `BaseRobot`

**Критерий завершения:**
- Planner принимает `Intent` и `WorldModel`, управляет роботом через `Robot API`
- Поведения работают детерминированно и объяснимо
- Код planner не зависит от типа робота (Sim/Real)
- Тесты проходят
